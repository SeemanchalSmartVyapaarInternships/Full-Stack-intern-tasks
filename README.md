* Authentication Systems
* GitHub Collaboration

## Workflow

1. Clone repository
2. Create feature branch
3. Read assigned GitHub Issue
4. Design solution architecture
5. Implement feature/module
6. Test functionality
7. Commit changes
8. Push branch
9. Create Pull Request
10. Address review comments
11. Merge approved code

## Branch Naming Convention

feature/task-name

Examples:

feature/admin-dashboard

feature/auth-rbac-system

feature/database-api-layer

feature/file-management-system

feature/medcarex-healthcare-system

## Pull Request Requirements

Every Pull Request must include:

* Task Summary
* Features Implemented
* Screenshots (Frontend Tasks)
* API Documentation (Backend Tasks)
* Testing Details
* Challenges Faced

## Coding Standards

* Follow MVC Architecture
* Write reusable code
* Use proper folder structure
* Use meaningful variable names
* Follow REST API standards
* Handle errors properly
* Write clean and maintainable code

## Database Standards

* Proper normalization
* Foreign key relationships
* Sequelize associations
* Migration-based development
* Secure database access

## Security Rules

* Never upload .env files
* Never commit secrets or API keys
* Implement input validation
* Use secure authentication practices
* Protect sensitive routes

## Important Rules

* Do NOT push directly to main branch
* Always create feature branches
* Follow issue requirements carefully
* Keep commits meaningful
* Maintain professional code quality
* Write scalable solutions
* Test before creating Pull Requests
